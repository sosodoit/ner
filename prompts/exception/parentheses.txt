## 괄호 표기 처리

### 적용 조건

개체명과 함께 괄호가 나타난 경우 (원어, 영문 표기, 한자, 약칭, 별칭, 부가 정보 등)

### 판단 절차

**1단계 — 괄호의 위치를 확인하세요.**

- 괄호가 개체명 **중간에 끼어** 있고, 괄호 뒤에 이어지는 부분이 개체명의 일부인 경우
  → 괄호를 포함하여 **전체를 하나의 태그**로 묶습니다. (통합)
- 괄호가 개체명 **뒤에 이어져** 있고, 앞부분만으로 개체명이 완결되는 경우
  → 앞 개체명과 괄호 안을 **분리하여 각각 판단**합니다. 괄호를 태그 안에 넣지 마세요. (분리)

**2단계 — 분리한 경우, 괄호 안의 내용을 판단하세요.**

- 앞 개체명과 **같은 대상을 가리키는 다른 표기**(원어, 한자, 영문, 로마자, 약칭, 별칭, 활동명)
  → 앞 개체명과 **동일한 태그**를 부여합니다.
- **다른 개체명**(국적, 소속 기관, 소재지, 작품명, 소속팀 등)
  → 그 개체명에 맞는 태그를 부여합니다.
- **개체명이 아닌 설명 정보**(나이, 순위, 직책, 수치, 날짜, 성별)
  → 태깅하지 않습니다.
- 개체명의 일부를 이루지 않는 **접미사나 단위어 조각**(誌, 氏, 君, 山 등)
  → 태깅하지 않습니다.
- 현재 태깅 대상이 아닌 범주(CV 등)이거나 어떤 태그에도 해당하지 않는 내용
  → 태그 없이 그대로 둡니다.

**3단계 — 괄호 안에 여러 항목이 나열된 경우, 항목마다 2단계를 따로 적용하세요.**

### 원칙

- 괄호 기호 `(`, `)`는 분리한 경우 항상 태그 밖에 둡니다.
- 태그 안에 괄호를 포함한 형태(`<투어스(TWS): PS>`)로 출력하지 마세요. 괄호가 개체명 중간에 끼어 있는 경우에만 허용됩니다.
- 태그 안에 다른 태그를 중첩하지 마세요. 괄호를 분리하기로 판정했으면 앞 개체명의 태그를 괄호 앞에서 닫고, 괄호 안에 별도의 태그를 엽니다. `<A(<B: X>): Y>` 형태는 허용되지 않습니다.
- 1단계에서 **통합**으로 판정한 경우에는 괄호 안에 별도의 태그를 부여하지 마세요. 괄호와 그 내용은 태그 안에 그대로 포함됩니다.
- 앞 개체명과 괄호 안 표기가 같은 대상을 가리키더라도, 두 표현에 각각 태그를 부여합니다. 하나로 합치지 마세요.
- 괄호 안이 앞 개체명과 **같은 대상의 다른 표기**인 경우에만 앞 개체명의 태그를 따릅니다. 형태가 영문이라는 이유로 다른 태그를 부여하지 마세요.
- 괄호 안이 앞 개체명과 **다른 대상**인 경우에는 앞 개체명의 태그를 따르지 말고, 그 대상 자체의 범주로 판단하세요. 앞 개체명이 PS라는 이유로 괄호 안도 PS로 태깅하는 오류를 주의하세요.
- 앞 개체명과 괄호 안 표기의 범주가 서로 다르더라도 각각의 판단을 유지하세요. 태그를 일치시키기 위해 어느 한쪽을 바꾸지 마세요.
- 괄호 안의 ‘이하’, ‘약칭’, ‘구’, ‘현’, ‘옛’ 등 관계를 나타내는 말은 태그 범위에서 제외합니다.
- 괄호 뒤에 조사가 이어지는 경우 조사는 태그 밖에 둡니다.

### 예시

**분리 — 같은 대상의 다른 표기 (태그 동일)**

- 투어스(TWS)가 데뷔했다
→ `<투어스: PS>`(`<TWS: PS>`)가 데뷔했다
- 방탄소년단(BTS)
→ `<방탄소년단: PS>`(`<BTS: PS>`)
- 수월관음도(水月觀音圖)
→ `<수월관음도: AF>`(`<水月觀音圖: AF>`)
- 국가수사본부(국수본)
→ `<국가수사본부: OG>`(`<국수본: OG>`)
- 한국문화예술위원회(이하 문예위)
→ `<한국문화예술위원회: OG>`(이하 `<문예위: OG>`)

**분리 — 다른 대상 (태그 각각 판단)**

- 봉준호(기생충)
→ `<봉준호: PS>`(`<기생충: AF>`)
- 손흥민(토트넘)
→ `<손흥민: PS>`(`<토트넘: OG>`)
- 아이브(스타쉽엔터테인먼트)
→ `<아이브: PS>`(`<스타쉽엔터테인먼트: OG>`)
- 샤라포바(러시아, 2위, 28세)
→ `<샤라포바: PS>`(`<러시아: LC>`, 2위, 28세)

**분리 — 괄호 안이 미태깅 대상**

- 김철수(45)는
→ `<김철수: PS>`(45)는
- 이코노미스트지(誌)는
→ `<이코노미스트지: OG>`(誌)는
- 국토교통부(4대강 사업 담당)
→ `<국토교통부: OG>`(4대강 사업 담당)

**통합 — 괄호 안은 태깅하지 않음**

- 퓨(Pew)공익재단의
→ `<퓨(Pew)공익재단: OG>`의 (`<퓨(<Pew: OG>)공익재단: OG>` 형태로 출력하지 마세요)
- 톄링(鐵嶺)시
→ `<톄링(鐵嶺)시: LC>`

### 태깅하지 않는 경우

- 괄호 안이 설명 정보뿐인 경우 : 나이, 순위, 직책, 수치, 날짜, 성별
- 괄호 안이 접미사·단위어 조각인 경우 : (誌), (氏), (君)
- 괄호 안이 현재 태깅 대상이 아닌 범주(CV 등)인 경우

---

## 검수 시 확인 사항 (괄호 관련)

1. 기존 태그 범위에 괄호가 포함되어 있으면, 괄호가 개체명 중간에 끼어 있는 경우인지 확인합니다. 개체명 뒤에 부가 정보로 붙은 괄호라면 통합·분리 오류 여부를 검토합니다.
2. 기존 태깅에 태그 중첩이 있으면 형식 오류 후보로 기록합니다. `<A(<B: X>): Y>` 형태는 허용하지 않습니다.
3. 괄호 안에 앞 개체명의 다른 표기(원어, 영문, 약칭)가 태깅되지 않은 경우에는 실제로 같은 대상을 가리키는지 확인하고, 명확한 경우에만 누락 후보로 기록합니다.
4. 괄호 안의 태그가 앞 개체명의 태그와 같더라도 두 표현이 실제로 같은 대상을 가리키는지 확인합니다. 다른 대상이면 범주 오류 후보로 판단합니다.
5. 하나로 통합되어야 할 표현 안에 별도 태그가 중첩되어 있지 않은지 확인합니다.
6. 괄호 안의 ‘이하’, ‘약칭’, ‘구’, ‘현’, ‘옛’ 등이 태그 범위에 불필요하게 포함되어 있지 않은지 확인합니다.

이 점검 항목은 기존 태깅의 오류를 찾기 위한 기준입니다. 기사 전체를 새로 태깅하거나 괄호 표현을 일괄 태깅하라는 지시가 아닙니다.
