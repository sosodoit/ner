# 입력 형식 및 문맥 판단 원칙

## 1. 입력 형식

입력은 기사에 포함된 문장들을 다음 형식으로 제공합니다.

[문장 ID] 기존 태깅이 적용된 문장

- 대괄호 안의 문장 ID는 원본 문장을 식별하기 위한 메타데이터입니다.
- 문장 ID와 대괄호는 실제 기사 본문에 포함된 내용이 아니므로 개체명 검수 대상에서 제외합니다.
- 문장 ID는 결과에 그대로 유지하며 임의로 변경하거나 생성하지 않습니다.
- 여러 문장은 동일 기사에 속하므로 개별 문장뿐 아니라 다른 문장의 내용도 필요한 경우 문맥 판단에 활용합니다.

## 2. 기존 태깅의 해석

- 입력에 표시된 <개체명: TAG>는 기존 개체명 태깅 결과이며, 정답으로 전제하지 않습니다.
- 꺾쇠 괄호 안에서 콜론 앞의 표현은 실제 문장에 등장하는 개체명 후보 표현이며, 콜론 뒤의 TAG는 해당 표현에 부여된 기존 태그입니다.
- 문맥을 판단할 때는 태그 문자열 자체가 아니라 태그 안의 개체명 표현이 문장에서 실제로 무엇을 지칭하는지 해석합니다.
- 기존 태그가 올바른지는 해당 표현의 의미와 지칭 대상, 문장의 서술어 및 주변 문맥을 바탕으로 독립적으로 판단합니다.
- 표현 자체의 형태나 기존 태그만으로 개체의 의미와 범주를 단정하지 않습니다.

## 3. 검수 범위

- 기존에 태깅된 개체명의 개체명 여부, 태그 범주 및 태깅 범위를 검수합니다.
- 문장 전체를 확인하여 태깅 누락 가능성이 있는 개체명도 검토합니다.
- 공통 원칙, 해당 태그별 규칙, 예외사항 및 오류 유형별 규칙을 적용합니다.
- 기존 태깅이 올바른 경우에도 review_status를 normal로 설정하여 검수 결과에 등록합니다.
- 오류가 발견된 경우 review_status를 error로 설정하여 검수 결과에 기록합니다.
- 오류 여부 또는 수정안이 불확실한 경우 검수 결과에 기록하고 review_needed를 true로 설정합니다.
- 입력으로 제공된 모든 문장에 대해 최소 하나의 검수 결과를 반환합니다.

## 4. 수정 구간 작성 원칙

- target_span에는 수정이 필요한 원문의 정확한 구간을 기록합니다.
- 기존 태깅 오류는 입력에 표시된 기존 태그를 포함하여 해당 구간을 그대로 기록합니다.
- 태깅 누락은 태그가 누락된 원문의 정확한 표현을 기록합니다.
- corrected_span에는 target_span을 대체할 정확한 수정 내용을 기록합니다.
- 태깅을 추가하거나 태그를 변경하는 경우 수정된 <개체명: TAG> 형식으로 작성합니다.
- 태깅 제거가 필요한 경우 태그를 제거한 표현을 작성합니다.
- 범위 확장, 범위 축소, 태깅 분리 및 태깅 병합은 오류 구간 전체에 적용할 수 있도록 수정 내용을 작성합니다.
- 문장 전체를 다시 작성하지 말고 수정이 필요한 구간만 반환합니다.
- 입력에 없는 표현을 임의로 추가하거나 원문의 띄어쓰기, 문장부호 및 표기를 임의로 변경하지 않습니다.
- 수정 구간을 정확히 판단하기 어렵거나 수정안이 불확실하면 추측하지 말고 review_needed를 true로 설정합니다.

## 5. 출력 원칙

- 지정된 JSON Schema에 맞는 결과만 반환합니다.
- 오류 유형, 수정안, 검수 근거 및 휴먼 검수 필요성을 기록합니다.
- 오류가 없는 문장이나 올바른 기존 태깅은 review_status를 normal로 설정하여 reviews에 등록합니다. 이 경우 target_span, corrected_span, error_lv1, error_lv2는 null로 설정합니다.
- 문장 ID는 입력에 있는 값을 그대로 사용합니다.
- 별도의 설명, 분석, 서두 및 맺음말은 출력하지 않습니다.
